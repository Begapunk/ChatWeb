## 1. 产品目标与 M1 边界

### 1.1 产品目标（M1）

1. **准入闭环**：4 人固定成员的注册准入全链路可用——邀请码生成→校验→Synapse 注册令牌发放→注册→自动进入私人加密房间，全程无匿名入口。
2. **服务器零信任边界**：管理 Token、共享密钥等机密只存在于服务端环境变量/Docker secrets；浏览器/公网永远无法触达 `/_synapse/admin` 与邀请服务管理端点；联邦与公开注册关闭。
3. **可运维基线**：Docker Compose 一键部署（镜像源参数化），部署检查脚本逐项断言安全配置，备份/恢复/升级文档占位与 `.env.example` 齐备，为 M2 前端开工提供稳定地基。

### 1.2 M1 边界（明确不做）

|---|---|
| 前端 UI（登录页/聊天界面/注册页） | M2 |

| 附件加密 | M4 |

M1 的"注册流程"以 **API + 脚本** 验证，不要求浏览器界面。

## 2. 用户故事

- **US1（管理员发放邀请码）**：作为管理员，我想通过受保护的命令行/管理端点生成一个一次性邀请码并设定有效期，以便只邀请我信任的那位朋友，且不怕邀请码泄露后被滥用。
- **US2（受邀者凭码注册）**：作为受邀者，我想拿着邀请码换取注册凭证并完成注册，以便无需管理员代管密码，自己掌握账号与加密密钥。
- **US3（第 5 人被拒）**：作为系统外部人员，当 4 个正式名额已满时，即使我持有有效邀请码，注册也应被拒绝，以保护四人隐私边界。
- **US4（注册即入群聊）**：作为新注册成员，我想在注册成功后立即出现在固定四人加密群聊与相应私聊房间中，以便无需任何手动配置即可开始使用。
- **US5（运维者部署与验收）**：作为部署者，我想一条命令拉起全部服务并运行部署检查脚本，逐项确认联邦关闭、访客禁用、管理 API 不外露、注册必须令牌，以便对安全配置有可复核的证据。

## 4. 邀请码生命周期状态机

```
                生成（安全随机, 存加盐哈希）
                       │
                       ▼
                 ┌───────────┐
      管理员分发 │  UNUSED   │（等待校验, attempts=0）
       ────────▶ └────┬──────┘
                     │ 受邀者提交校验
                     ▼
              ┌─────────────┐   哈希不匹配/未过期未超限
              │  VALIDATING │ ────────────────────────┐
              └──────┬──────┘  attempts+1, 仍在 UNUSED │
                     │                                    │（attempts < max）
       ┌─────────────┼────────────────────────────────────┘
       │             │ 校验全部通过（名额事务内）
       │             ▼
       │      ┌───────────┐  发放 uses_allowed=1 的
       │      │   USED    │  Synapse 注册令牌（短有效期）
       │      └───────────┘
       │
       │  到达 expires_at ──▶ EXPIRED（终态）
       │  attempts ≥ max  ──▶ BLOCKED（尝试超限, 终态）
       │  管理员作废     ──▶ REVOKED（终态）
       └── 终态码与 UNUSED 在校验响应中区分：
           过期→"expired"，超限→"blocked"，已用→"used"，
           令牌过期后重来→需新邀请码（不复活旧码）
```

**次数限制语义**：
- `max_attempts`（默认 5）统计**校验失败**次数（哈希不匹配视为对该码的一次尝试）；校验成功不计入。
- 一次性：校验成功即转 `USED`，后续任何提交返回"已使用"，无论注册是否最终完成。
- **注册失败补偿**：若 Synapse 令牌已发但受邀者未在令牌有效期内完成注册（码已 USED），默认**不自动复活**，管理员需生成新码（见 §6 Q2）。
- 名额不足（已满 4 人）时校验直接失败返回 `quota_exhausted`，邀请码**不消耗**（保持 UNUSED），便于删号后重用（若未来支持）。
- 哈希存储：库中不存明文码；明文仅在生成响应中一次性返回给管理员。

## 5. 验收标准（Given/When/Then）

以下每条都必须出现在 M1 集成测试中并可自动化复跑（吸收 M0 风险 R2.1–R2.4、TODO"集成测试"项）。

**A. 邀请码重复使用**
- Given 一个已成功用于注册的邀请码，When 再次用该码请求校验，Then 返回 4xx，错误码为 `used`，且不发放新的注册令牌。

**B. 过期邀请码**
- Given 一个 `expires_at` 已过去的 UNUSED 邀请码，When 提交校验，Then 返回 4xx，错误码 `expired`，`attempts` 不增加（过期判定先于尝试计数）。

**C. 尝试超限**
- Given 一个 `max_attempts=3` 的 UNUSED 邀请码，When 连续提交 3 次错误值（对同一码的哈希不匹配），Then 第 3 次后该码转 BLOCKED；第 4 次即使提交正确明文也返回 `blocked`，不发放令牌。

**D. 四人上限**
- Given 系统已有 4 个正式账号（含管理员），When 持有全新有效邀请码者提交校验，Then 返回 4xx `quota_exhausted`，不调用 Synapse 令牌 API，邀请码保持 UNUSED。

**E. 并发注册竞态不多发名额**
- Given 剩余 1 个名额且存在 ≥8 个并发有效校验请求（各自持不同有效邀请码），When 全部并发提交，Then 恰好 1 个成功获得注册令牌，其余返回 `quota_exhausted`；最终账号总数 = 4（名额计数无超卖，数据库事务无死锁）。

**F. 注册后自动进入加密房间**
- Given 一个新用户通过邀请码+注册令牌完成 `m.login.registration_token` 注册，When 注册脚本以该用户身份 sync，Then 用户收到固定四人群聊与指定私聊房间的邀请并可 join；join 后发送的消息在房间内为 `m.room.encrypted`（Megolm 密文），另一成员可解密。

**G. 管理 API 不对浏览器暴露**
- Given 部署完成的服务，When 从公网入口（经 Caddy，模拟浏览器路径）请求 `/_synapse/admin/*`、`/_synapse/rest/admin/*` 及邀请服务的管理端点（不带服务端管理密钥），Then 均不可达（404/拒路由）或被拒（401），不泄露任何管理能力；`docker inspect` 断言管理 Token 只以环境变量/secret 形式存在于服务端容器。

**H. 联邦关闭**
- Given 部署完成的服务，When 检查运行中 homeserver.yaml 生效配置并尝试从外部联邦域名发起 `/joined_servers` 类联邦查询，Then 联邦白名单为空、无已知联邦服务器；部署检查脚本对此逐项断言通过。

**I. 公开注册与访客关闭**
- Given 部署完成的服务，When 不带注册令牌直接调用 `/register`（`kind=guest` 与匿名注册），Then 均被拒绝；带已用尽 `uses_allowed` 的令牌注册返回 401（M0 已实测语义）。

**J. 部署检查与运维占位**
- Given 一台新机器（或干净环境）与 `.env.example` 填好真实值，When 执行部署与检查脚本，Then 全部服务健康、检查报告 100% 通过；备份/恢复/升级三份文档占位与 `.env.example` 存在且无真实机密值入库（git 历史 `git log -p` 扫描无 token）。
