# Aether 无服务器 P2P 分支状态

分支：`feat/aether-serverless-p2p`。本分支保留原 Matrix 和 Cloudflare 文件；正式 P2P 首页在 `/`，原界面入口暂留 `/legacy`。没有部署后端或购买服务，也没有推送或发布本分支。

## 已实现并做过本机浏览器验证

- 每台设备独立生成 Ed25519 签名密钥、X25519 交换密钥；Argon2id 口令派生密钥加密本地保险箱。
- 手动 Offer/Answer 文本连接码、二维码分片和重组、签名与过期检查；二维码在浏览器本地生成和扫描。
- 禁止 TURN 配置和 relay 候选；最多 4 名成员；WebRTC DataChannel 建立直接连接。
- 指纹核对后才允许房间邀请、密文消息、附件和同步；房间密钥单独封装给受邀设备。
- XChaCha20-Poly1305 消息和附件加密，消息 Ed25519 签名；IndexedDB 保存密文、设备、房间、附件与待发队列。
- Lamport 时间戳、发送者序号、唯一 ID 去重；三节点中转保留原始签名、TTL 限制、签名副本确认。
- 成员加入时同步签名成员表；房主移除成员时轮换房间密钥并向在线剩余成员分发。
- 文本、图片和文件（单个至多 2 MiB）、录制语音文件与本机播放；附件分块传输、SHA-256 校验、DataChannel 缓冲限速。
- 文字消息回复、表情回应、撤回和本机消息搜索；这些操作作为签名密文事件同步，撤回不能擦除已经保存在其他设备的旧密文。
- 本机网络诊断：手动标注运营商/连接方式，逐个测试 STUN 候选，导出不含 IP 的本地报告。
- GitHub Pages 子路径构建、PWA 缓存和手动触发的 Pages 工作流；刷新子路由使用 `404.html` 回退。

自动化验证包括加密、存储、信令的单元测试，以及四个互相隔离的 Edge 浏览器配置文件中的真实 WebRTC DataChannel 测试。浏览器测试覆盖第四人入房、B 经 A 向 C 转发、D 经 A 向 B 转发、四份副本确认、附件密文传输后字节一致性、房间密钥轮换、刷新后解锁并读取历史和移除状态；还检查传输帧中没有测试消息和附件的明文。这些是**本机浏览器测试**，不是不同运营商、不同手机或中国大陆无 VPN 实测。

## 重要限制

1. 没有信令服务器时，初次配对和网络地址变化后的 ICE Restart 都需要重新交换连接码。浏览器会尝试维持现有连接，但无法承诺断线后自动恢复。彻底失联且无其他在线节点时，无法自动发现对方。
2. 禁用 TURN 后，CGNAT、对称 NAT、UDP 受限网络可能完全无法直连；节点中转只有已连通节点在线时可用。不能保证所有运营商组合成功。
3. 文件分片只在当前页面的内存中重组。刷新、退出或网络中断后需要从头传输；尚无跨会话断点续传、进度条或持久传输队列。单文件限制 2 MiB。
4. 房主移除成员后，已离线成员暂时不会收到移除提示，仍可能看到旧的本地房间；其旧密钥不能解密新轮次消息。已发出的旧消息无法远程删除。移除者之后的消息在房主端会被拒绝。
5. 当前未实现完整未读统计、消息编辑、实时语音通话、自动节点辅助信令和四台真实手机的网络切换验证。原演示界面保留在 `/legacy`，不可把其假消息当作正式 P2P 聊天结果。
6. 加密使用成熟算法和 libsodium 实现，但设备入群、成员同步、转发与副本协议是本项目代码，**未经独立安全审计**。不应当用于高风险保密场景。
7. 加密设备密钥导出不包含本地聊天记录和附件。恢复密钥后仍需与有副本的成员重新配对和同步；若所有副本丢失，历史无法恢复。JavaScript 中的密钥字符串不能保证即时从内存清除。
8. 手机 PWA 在后台或锁屏后可能被系统暂停，无法保证始终在线或接收消息。

## 本机使用

在 `frontend` 文件夹运行 `npm ci`，然后 `npm run dev`。浏览器打开本地地址。双方分别创建设备并记住口令；一方创建房间并生成发起码，另一方粘贴或扫描后生成应答码，再由发起方输入应答码。连接成功后，双方当面核对完整设备指纹并点击信任；房主邀请对方入房。可重复配对另外两台设备。

连接码包含 SDP/ICE 网络信息，不要公开发布。若一方没有得到二维码，使用文本连接码安全地交换。添加或删除 STUN 地址后需要生成新的连接。当前默认的公共 STUN 地址只是候选示例，未在你的运营商网络验证；STUN 只用于地址发现。

默认 STUN 候选来源为 Google 公共 STUN 示例 `stun:stun.l.google.com:19302` 和 `stun:stun1.l.google.com:19302`。截至 2026-11-26，本项目**没有**在目标运营商网络完成验证，因此没有可靠性验证日期；诊断页会逐个报告本机当次检测结果，不会把地址标成“可靠”。用户可自行添加其他公共 STUN，默认两项属于同一服务提供方，不构成跨服务商冗余。

## GitHub Pages 发布步骤（待用户另行授权）

目标仓库是 `Begapunk/ChatWeb`，当前为**私有仓库**。GitHub Free 的 Pages 发布要求仓库公开；不要为发布而擅自更改仓库可见性。若以后决定公开源码，可在仓库设置中把 Pages 来源设为 **GitHub Actions**，再在 Actions 页面手动运行 `Aether GitHub Pages`。工作流只在手动触发时执行，不会自动发布。构建使用 `/ChatWeb/` 子路径；成功后地址预计为 `https://begapunk.github.io/ChatWeb/`，实际地址应以 Actions 部署结果为准。私有仓库保持现状时，不应宣称已有 Pages 测试网址。

仓库和 Actions 只存放程序文件。不要把设备口令、保险箱备份、连接码、聊天消息、附件或诊断报告提交到 Git。

## 真实设备测试记录方法

每台设备安装 PWA 前先在 Safari 或 Chrome 访问 Pages HTTPS 地址，检查离线启动和解锁。按“移动↔电信、移动↔联通、移动↔广电、电信↔联通、电信↔广电、联通↔广电、各运营商↔Wi-Fi、不同 Wi-Fi、VPN 开/关、IPv4/IPv6”逐组记录：设备和浏览器、手动确认的网络类型、STUN 候选数、连接是否成功、实际候选路径与 RTT、配对耗时、双向消息、附件、断线与重连结果。先用网络诊断页导出本机报告，再记录实际两端聊天结果。任何未测组合应标为“未测试”，失败组合记录错误及是否必须重扫码。
