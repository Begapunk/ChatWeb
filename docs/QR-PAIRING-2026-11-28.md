# 扫码添加设备（2026-11-28）

Aether 继续由 GitHub Pages 托管，连接仍是 WebRTC P2P；不引入新的信令服务器、数据库或 TURN。

## 日常操作

1. Alice 在“设置”打开“我的设备二维码”。这是包含公开设备身份和一次性 WebRTC 发起信息的二维码，有效期 15 分钟。
2. Bob 在“联系人”点“扫一扫”，扫描 Alice 的二维码。Bob 的手机显示一张应答二维码。
3. Alice 点“扫描对方应答”，扫描 Bob 的二维码。双方通过签名信令和当前加密连接证明身份，随后自动建立私聊，无需复制连接码或手动输入验证码。

添加设备码在到期前一分钟自动刷新；手机从后台恢复时也会检查有效期。请以当前屏幕显示的二维码为准。

这是纯静态网页能够实现的最少**双向**光学交换。原截图中的长期“设备身份二维码”只含公开身份，不含当前网络连接信息，因此单扫它只能核对身份，无法让两部手机自动建立 WebRTC 连接。现在日常入口展示的是一次性“添加设备二维码”；长期身份码收在“我的设备身份与备份”中。

若某台设备拒绝摄像头权限、浏览器不支持二维码压缩，或当前 ICE 信息超出单张二维码容量，可展开“高级连接码”使用原有文本/多码方式。此降级不会把未连接设备标记为已连接。

## 免费信令服务调查

- EMQX 提供公共 MQTT Broker，支持 WSS；本机曾成功建立 WebSocket 握手。但其官方页面明确定位为原型、学习和测试，并警告公共 Broker 消息对其他用户可见，不可发送敏感数据。它不能作为私人聊天软件默认信令通道，也无法用本机连接成功证明中国大陆不同手机网络可用。来源：[EMQX 免费公共 Broker](https://www.emqx.com/zh/mqtt/public-mqtt5-broker)。
- EMQX Cloud 私有 Serverless 服务有免费额度，但超额采用按量付费；不符合本项目“不引入付费资源”的固定要求。来源：[EMQX Cloud 免费额度说明](https://docs.emqx.com/en/cloud/latest/deployments/alerts_guide/free_minutes_limit_reached.html)。
- PeerJS 提供免费公共信令服务器，但没有足够证据证明在目标中国大陆网络稳定可用；接入还会替换现有身份绑定的信令路径，因此本轮没有采用。来源：[PeerJS Cloud](https://peerjs.com/server/cloud)。

未使用上述服务，也没有上传聊天内容或连接码到它们。真实手机扫码、iOS Safari/PWA、运营商组合仍需现场验收。
