# Aether P2P 升级记录（2026-11-27）

本记录只描述 `feat/aether-serverless-p2p` 分支的当前源码与本机测试。GitHub Pages 仅托管静态应用。Matrix 与 Cloudflare 历史源码仍保留。

## 已实现

- 长期 Ed25519/X25519 设备身份保存在原有加密保险箱；新增 SHA-256 身份公钥指纹与仅含公开信息的身份二维码。旧 BLAKE2b 设备 ID 保留，以免破坏原有身份和数据。
- Offer/Answer 签名信令与本次 WebRTC 会话 transcript 绑定；双方通过签名挑战证明持有长期身份私钥。8 位安全验证码由双方身份、签名信令 transcript 和随机挑战经 HKDF/SHA-256 派生。扫码身份码也必须与当前完成挑战的连接一致。首次确认后持久保存信任；重连重新挑战并自动识别已信任身份。身份不符时拒绝定向重连，保留旧信任记录。
- 独立双人私聊房间与群聊房间、独立密钥和成员名单。私聊消息只向指定对端发送，不经群聊转发。群聊新增成员时轮换密钥；移除成员时再轮换。新成员不能解密轮换前的历史消息。
- 签名送达回执及签名已读回执。未读消息在用户打开会话并成功解密后才发送已读回执。待发密文保存在 IndexedDB，在线重试采用指数退避；可手动重试或停止后续重发。停止重发无法收回已送达副本。
- 保留文字、表情、回复、撤回、图片/文件与录制语音消息。新增本地消息删除、会话记录删除、未读数量与消息复制。删除时本机保留最小化消息 ID 标记，以避免其他设备同步时自动恢复已删除内容。新增已认证私聊中的一对一 WebRTC 语音通话；对方需明确接听并授予麦克风权限。
- 消息、联系人、设置三栏；设置展示本机身份与二维码，联系人展示安全验证码、身份状态与备注。网络诊断仍是独立页面。

## 使用步骤

1. 两台设备分别打开同一 GitHub Pages 地址并创建本机设备，保管好口令与加密设备备份。
2. 在“联系人”中展开“添加设备”。一方生成发起码，对方扫描或粘贴后生成应答码，发起方再输入应答码。连接码包含网络候选地址，只交给要连接的人。
3. 两端在“联系人”看到相同的 8 位验证码后，当面核对并分别点击“验证码相同，确认信任”；也可扫描对方“设置”中的公开身份二维码。完整 SHA-256 指纹是备用核对方式。只有单方确认时，只能由已确认的一方发起邀请，对方尚不能正常聊天；双方均需确认。
4. 点击“发起私聊”即可两人通信；群聊由创建者创建并邀请已认证联系人。语音通话仅在私聊中出现，对方点击“接听”后才会开始双向音频。
5. 断线后本机消息留在待发队列。恢复原连接时自动尝试补发；如果 WebRTC 无法恢复，双方需要再次交换连接码。已保存的信任记录会在新连接完成签名挑战后自动验证。

## 本机验证

- `npm run typecheck`、`npm test`（45 项）通过。
- `node e2e/p2p-identity.mjs`：两个隔离 Edge 浏览器中的签名会话验证码、信任门禁、私聊密文、真实已读回执与语音协商通过。音频轨道是测试生成的合成音频，未验证真实麦克风、扬声器或手机权限。
- 同一浏览器测试还覆盖页面刷新后重新交换码并自动认证，以及同名新密钥被阻断、旧新 SHA-256 指纹展示。两台不同设备若故意使用相同名称也会触发保守阻断；撤销旧信任后才能重新配对。
- `node e2e/p2p-local.mjs`：四个隔离 Edge 浏览器中的群聊、密文转发、单组私聊与群聊隔离、附件、回执、密钥轮换、刷新持久化通过。六组私聊同时建立尚未自动化验证。
- `VITE_BASE_PATH=/ChatWeb/ npm run build:pages` 通过，生成 PWA Service Worker 与 GitHub Pages `404.html` 回退文件。

以上不是四台手机、跨运营商、iOS Safari 或中国大陆无 VPN 网络实测。

## 安全和架构限制

- 长期私钥仍使用已有 libsodium 格式并存放于 Argon2id 加密保险箱。为保留既有身份和备份，尚未迁移为 Web Crypto 不可导出私钥；解锁后 JavaScript 内存中有可导出的私钥材料。
- Ed25519、X25519、XChaCha20-Poly1305、Argon2id、SHA-256 与 HKDF 使用成熟实现；设备认证、群成员管理及会话协议组合仍是本项目代码，未经独立安全审计。8 位验证码只能防止高概率误配，不能代替可信的当面/独立渠道核对。
- 身份变化检测针对已信任的设备 ID、定向重连和同名新身份；如果攻击者改用完全不同的名称与设备 ID，应用无法知道它原本想冒充哪个联系人，首次验证仍需用户当面核对。
- 无中心信令和 TURN。CGNAT、对称 NAT、UDP 受限网络可能无法直连；断线且没有可用通信通道时无法自动交换新的 SDP。STUN 不提供中继。后台、锁屏、PWA 被系统挂起时不能保证在线或接听来电。
- 已撤销信任的设备可保留撤销前已取得的密钥和消息；群主撤销时会移除成员并轮换密钥。非群主无法单方面阻止其他成员继续向该设备发送旧群密钥下的消息，须请群主移除并轮换。
- 已送达与已读只代表收到签名回执；不能证明对方没有复制消息。消息撤回不能删除对方已保存的内容。离线消息只保存在发送方设备，不能伪称已送达。
- IndexedDB 聊天记录、附件及待发密文未单独进行静态加密封装；消息正文与附件本身是端到端密文，房间密钥在加密保险箱中。房间名称、设备名称、成员、时间与状态等元数据保留明文。浏览器清理站点数据会导致本地记录丢失。
- 还没有完成完整自动 ICE Restart、跨会话附件续传、语音通话网络切换恢复、协议兼容迁移与正式安全审计。本阶段不得宣称这些能力已经完成。浏览器删除 IndexedDB 记录不能保证底层存储介质的物理擦除。
